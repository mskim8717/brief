# 국회 보고서 근거표

## 범위
- 읽기: `input/A_*.txt`, `input/B_*.txt` 두 파일만 읽는다(`sources/`의 PDF는 열지 않는다).
- 쓰기: `output/보고서_근거표.md`에만 쓴다(있으면 덮어쓴다).
- URL은 열지 않고 입력 메타 정보에 적힌 그대로 옮긴다.

## 작성 기준
1. 보고서마다 **따로** 표를 만든다(`## A …`, `## B …`). 두 문서를 한 표·한 문장으로 합치지 않는다.
2. 표는 `항목 | 내용 | PDF쪽` 3열이다. 항목(행)은 아래 9개를 이 순서로 쓰고, 근거 쪽은 PDF쪽 열에 쓴다.
   - 기관, 발행일, 문서유형(3행) ← 메타 정보
   - 문제 ← 문서가 제기한 문제
   - 핵심 주장 ← 문서의 주된 결론
   - 정량값 또는 조문 ← A는 숫자(단위 포함), B는 조문 번호. 원문 글자 그대로. 조문은 법률명별로 묶고, 법률명 없이 나온 조문은 B가 다루는 법률의 조문으로 묶는다
   - 제언 ← 문서가 제시한 과제·개선 방향(번호 매긴 것은 모두)
   - 해석 주의 ← 문서 스스로 밝힌 전제·한계, 시행 전 계획·예정 사항, 추출 주의
   - 원문 URL ← 메타 정보 그대로
3. PDF쪽은 입력의 `=== PDF n쪽 ===` 표시를 따른다. B의 `[왼쪽 단]`·`[오른쪽 단]`은 쪽 안의 위치일 뿐이다.
4. 숫자·조문·날짜·한계 문구는 입력과 글자 단위로 대조한다. 그림의 숫자처럼 추출이 흐트러진 곳, 확신이 없는 곳은 `확인 필요`라고 쓴다.
5. 입력에 없는 사실·수치·평가를 덧붙이지 않는다. "예정", "할 계획", "검토할 수 있다" 같은 표현을 확정된 사실로 바꾸지 않고, "대부분"·"모두"처럼 문서 전체를 평가하는 말을 새로 만들지 않는다.

## 저장 형식
```markdown
# 국회 보고서 근거표

## A. <문서유형·호수> — <제목>
| 항목 | 내용 | PDF쪽 |
|---|---|---|

## B. <문서유형·호수> — <제목>
| 항목 | 내용 | PDF쪽 |
|---|---|---|

## 감사연구원용 보고 메모
- (3–4줄. 줄마다 A 또는 B를 밝힌다. 두 문서는 서로 다른 기관의 별개 보고서이며, 같은 연구 결과처럼 묶지 않는다.)

> 입력: input/A_*.txt, input/B_*.txt · 입력에 없는 사실은 추가하지 않음
> 출처표시: (각 입력 메타 정보의 출처표시 문구를 그대로)
```

## 마치기 전 점검
- 표가 2개이고 각 9행(머리줄 제외)인가?
- 숫자·조문·날짜·URL이 입력과 같은가? PDF쪽이 맞는가?
- 메모가 3–4줄이고, 입력 밖 사실이나 두 문서를 합친 결론이 없는가?

결과 보고는 저장 경로와 표·메모 줄 수만 짧게 쓴다.
